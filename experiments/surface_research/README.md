# Проверка точности поверхностей промышленной КТ

Исследование от 2 ноября 2026 года. Сравнение выполнено на исходных 16-битных
TIFF `img_0500..img_1000`, 910×1804. Подробный разбор — `RESEARCH.md`.

**[Готовые изображения, метрики и координаты среза 0750](results/README.md).**
Их можно открыть прямо в GitHub без установки Python и повторного запуска.

Получен воспроизводимый прототип субвоксельного определения **кандидатов**
поверхности с явными причинами отказа. Полная метрологически подтверждённая
поверхность переходного сечения пока не получена. Новые watershed-варианты
создают ложные поверхности или пропускают стенки, поэтому не заменяют основную
C++-программу. `main.cpp`, CMake проекта и исходные КТ не изменены.

`direct_surface_study.py` независимо ищет максимумы полного 3D-градиента без
обязательного сильного глобального hysteresis seed. Сравнивает local ISO50,
максимум производной, локальную cubic Taylor approximation и robust erf fit
на исходной яркости вдоль 3D-нормали. Сглаживание применяется при поиске
кандидата/направления, а координаты модели оцениваются по исходным данным.

`edge_seed_study.py` содержит два альтернативных 3D marker-controlled watershed:
маркеры с двух сторон перепада и маркеры экстремумов с локальной проверкой
материала. Оба остаются исследовательскими. `envelope_method.py` — ещё один
сравнительный способ многомасштабных локальных маркеров; он также не принят.
`boundary_study.py` сохранён из предыдущего опыта для воспроизводимого baseline.

`double_edge_fit.py` совместно оценивает две близкие границы с общей Gaussian PSF.
`real_double_profiles.py` проверяет эту модель на реальных профилях, для которых
single-step модель обнаружила противоположный соседний переход. Принятый fit
не устанавливает семантику «воздух/материал» и не доказывает размерную точность.

Установка из корня репозитория в отдельное окружение:

```bash
python -m venv work/ct-venv
work/ct-venv/bin/python -m pip install -r experiments/surface_research/requirements.txt
```

На Windows исполняемый Python будет `work/ct-venv/Scripts/python.exe`.
Далее `python` означает Python выбранного окружения.

```bash
python experiments/surface_research/direct_surface_study.py --source CT_Test --centers 625,750,875,988 --half 8 --out work/ct-direct
python experiments/surface_research/edge_seed_study.py --source CT_Test --centers 625,750,875,988 --half 8 --sigma 1 --seed-mode extrema --out work/ct-watershed
python experiments/surface_research/real_double_profiles.py --input CT_Test --profiles work/ct-direct --centers 750,875 --out work/ct-double
```

Номера — из имён исходных файлов, без перенумерации. Для direct comparison
требуются как минимум шесть настоящих соседних срезов по обе стороны центрального.
По умолчанию используется 17 срезов. Пропуски файлов отвергаются; копиями,
интерполяцией или искусственным Z-padding соседние данные не заменяются.

Экспериментальные параметры фильтра кандидатов вынесены в CLI:
`--sigma .85`, `--floor .006`, `--min-contrast .06`, `--min-coherence .75`.
Контраст и градиент даны для uint16/65535, не в HU. Эти ограничения выбирались
для данной выборки. Слабая настоящая граница также может быть отвергнута.
Нельзя подбирать их только по красивой картинке или количеству полученных точек.
Direct CLI сейчас рассчитан на изотропную сетку. Сам `refine_surface` принимает
`spacing_zyx`, но для анизотропного CLI нужно также преобразовать исходные
градиентные нормали и шаг семплирования; одной конвертации итоговых координат мало.
Поиск ограничен ROI `largest Otsu +14 px` внутри crop: отдельные слабые поверхности
за его пределами не обнаруживаются. Это ещё одна причина не считать его полным.

Для сравнения с **текущими** C++-детекторами создаётся отдельный адаптер:

```bash
python experiments/surface_research/prepare_cpp_baseline.py --source main.cpp --out work/cpp-baseline
cmake -S work/cpp-baseline -B work/cpp-baseline/build -DCMAKE_BUILD_TYPE=Release
cmake --build work/cpp-baseline/build --config Release
python experiments/surface_research/prepare_cpp_baseline.py --source main.cpp --out work/cpp-baseline --input CT_Test --binary work/cpp-baseline/build/baseline_runtime --centers 625,750,875,988
python experiments/surface_research/direct_surface_study.py --source CT_Test --cpp-root work/cpp-baseline --centers 625,750,875,988 --out work/ct-direct-with-baseline
```

OpenCV должен быть доступен CMake; при необходимости передайте `-DOpenCV_DIR=...`.
На Windows укажите фактический путь к `Release/baseline_runtime.exe`. Адаптер меняет
только пути, позиции в отсортированном TIFF-списке и сохранение диагностик.
Номера файлов явно сопоставляются позициям списка в `source_mapping.csv`.
Алгоритмы, ROI и пороги трёх исходных детекторов сохраняются; diff и хеши записаны.
Новый каталог результатов нужен для каждого запуска baseline.

Проверки на известной геометрии:

```bash
python experiments/surface_research/validate_profiles.py --output work/profile_validation.json
python experiments/surface_research/validate_double_edge.py --output work/double_validation.json
```

Проверяются известные плоскости, сфера, шум, наклон по Z, анизотропный шаг,
перекрытие тонких стенок, асимметричная PSF и неразрешимые пары границ. Ошибка
считается вместе с долей принятых профилей. Проверки не калибруют реальный скан.

Выходные данные direct comparison:

- `comparison_XXXX.png` — текущие детекторы и новые кандидаты, если передан baseline.
- `points_XXXX.csv.gz` — исходные координаты и все четыре оценки с флагами качества.
- `profiles_XXXX.npz` — те же массивы, нормали, контраст, невязка и причины отказов.
- `erf_points_XXXX.ply` — только принятые кандидаты, без искусственных связей и сетки.
- `metrics.json` — параметры, номера исходных срезов и диагностические количества.

Координаты Z,Y,X заданы в индексах центров исходных вокселей. В CSV/PLY
`source_z=750` означает плоскость `img_0750.tif`; дробный Z — положение между
реальными плоскостями. PLY записан в порядке X,Y,Z. Результаты не переводятся
в микроны: 75.4 мкм из C++ ещё не является независимой калибровкой.

В каждой оценке `accepted` обязателен. При отказе координата совпадает с seed,
а смещение равно нулю. Это **не измеренная** точка поверхности. Нельзя объединять
такие точки в «готовую» точную сетку. `*_candidate_shift_vox` в NPZ сохраняет
непринятую оценку только для диагностики. Доли принятых профилей относятся
к пулу кандидатов, а не к полноте физической поверхности.

Коды причины отказа суммируются как битовая маска:

| Бит | Причина |
|---:|---|
| 1 | Профиль выходит за данные или нормаль некорректна |
| 2 | Недостаточный положительный контраст/SNR |
| 4 | Максимум производной на границе окна поиска |
| 8 | Сильный соседний переход противоположной полярности |
| 16 | Нет локального пересечения полувысоты |
| 32 | Неприемлемая невязка/обусловленность модели |
| 64 | Оценка ширины размытия или смещения у ограничения |
| 128 | Нет площадок по сторонам или чрезмерный фоновой наклон |
| 256 | Невалидная локальная cubic Taylor approximation |
| 512 | Контраст ниже экспериментального порога интерфейса |
| 1024 | Недостаточная согласованность направления градиента |

Single-step и double-step модули имеют разные определения битов; для double-step
используйте `double_edge_fit.FLAGS`. Оценки стандартной ошибки fit описывают
только локальную модель, без ошибок PSF, коррелированного шума, артефактов и масштаба.
