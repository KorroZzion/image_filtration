# Поиск поверхностей КТ-детали

Исследовательский прототип для наружной поверхности и стенок внутренних каналов.
Сохраняет 16-битные исходные TIFF, реальные номера файлов и существующий `main.cpp`.
Текущие результаты: `/workspace/ct-boundary-results/final/REPORT.md`.

## Окружение

Проверено на Python 3.12. В подготовленной облачной среде:

```bash
cd /workspace/image_filtration
python3 -m venv --system-site-packages /workspace/.onboarding/ct-python
/workspace/.onboarding/ct-python/bin/python -m pip install --no-cache-dir -r experiments/requirements.txt
```

Для отдельного локального окружения можно создать обычный venv и установить тот же
`requirements.txt`. Результаты пишутся только в указанный каталог; повторный запуск
обновляет файлы результатов с теми же именами, поэтому для нового опыта выбирайте
новый `--output`.

## Воспроизведение основных опытов

```bash
cd /workspace/image_filtration
export OPENBLAS_NUM_THREADS=2
export OMP_NUM_THREADS=2
PY=/workspace/.onboarding/ct-python/bin/python
OUT=/workspace/ct-boundary-results/reproduced

"$PY" experiments/boundary_study.py --input CT_Test --output "$OUT"
"$PY" experiments/phantom_check.py --output "$OUT/phantom_metrics.json"
"$PY" experiments/review_results.py --input CT_Test --output "$OUT" --phantom "$OUT/phantom_metrics.json"
```

Основной опыт занимает несколько минут, включая 3D watershed и экспорт. Изображения
обрабатываются в исходном разрешении 910×1804. По умолчанию сравниваются срезы
500, 625, 750, 875, 988; объёмный блок — 976–1000. Параметры `--study-slices`,
`--first`, `--last`, `--skip-study`, `--skip-volume` позволяют ограничить работу.

Сравниваются глобальный Otsu, Otsu в ROI, маркерный random walker, маркерный watershed,
watershed с локальным ISO50 и максимумом градиента. Дополнительно проверяются
локальные минимумы/светлые гребни как маркеры для ярких каналов. В текущем опыте
первая схема лучше сохраняет тонкие стенки, вторая обнаруживает яркие каналы
толстого сечения, но не является универсальной заменой.

Объёмная сегментация использует 3D watershed; последующее уточнение точек выполняется
в XY-плоскости, со смещением не более 3 пикселей. Слабые профили сохраняют начальную
координату и помечаются `gradient_supported=0`. Субпиксельная запись координаты сама
по себе не доказывает субпиксельную точность измерения.

`review_results.py` также сравнивает центральный срез с сохранёнными результатами
C++-программы в `/workspace/.onboarding/ct-sample`. Это необязательное для самой
сегментации сопоставление опирается на подготовленную облачную среду. В том старом
запуске номер результата 1006 соответствует реальному файлу img_0988; новые скрипты
никакого перенумерования не используют.

## Прослеживание между срезами

Отдельный опыт переносит опорные области с соседнего среза и заново ищет границу
по градиенту в полосе неопределённости. Он менее зависит от абсолютной яркости,
но наследует ошибки начальной маски, может накапливать дрейф и пропускать новые
замкнутые полости. Обратный и прямой проходы сравниваются, чтобы обнаружить дрейф.

```bash
"$PY" experiments/track_boundaries.py --input CT_Test \
  --seed-mask "$OUT/volume/material_0988.png" \
  --seed-slice 988 --first 500 --last 1000 \
  --output /workspace/ct-boundary-results/tracking-reproduced
```

Сырые маски переноса находятся в `reverse` и `forward`; отдельно сохранены
уточнённые контуры избранных срезов в `reverse_examples` и `refined_examples`.

В выполненном опыте перенос **всей** маски был отклонён: после 488 переходов от
img_0988 к img_0500 внешний контур сильно ушёл внутрь материала. Прямой проход
остановлен; полный цикл для этого варианта не проверен. Промежуточные маски
`/workspace/ct-boundary-results/tracking` не являются рекомендуемым результатом.

## Гибрид: новая наружная оболочка, прослеживаемые внутренние каналы

```bash
"$PY" experiments/track_channels.py --input CT_Test \
  --seed-mask "$OUT/volume/material_0988.png" \
  --seed-slice 988 --first 500 --last 1000 \
  --output /workspace/ct-boundary-results/hybrid-reproduced

"$PY" experiments/review_hybrid.py --input CT_Test \
  --output /workspace/ct-boundary-results/hybrid-reproduced \
  --study-results "$OUT"
```

В этом варианте наружная опорная оболочка определяется заново по каждому
исходному срезу. Передаются только опорные области внутренних каналов и
подтверждённого материала; маркеры канала отбрасываются, если локальный
контраст с окружающей стенкой исчез. Соседние срезы обрабатываются от исходной
маски в обе стороны. Это последовательная 2D-сегментация со связью по Z,
а не совместная оптимизация всего объёма.

Скрипт сохраняет маски всех обработанных срезов в `masks` и наложения/CSV
избранных срезов в `refined_examples`. Он зависит от качества начальной маски
и способен пропустить новую изолированную полость без переданного маркера.
Автоматическая повторная инициализация всех каналов пока не реализована.
В выполненном опыте на img_0875 обнаружены пропуски нескольких видимых каналов.
Поэтому и этот вариант остаётся диагностическим и не принят как способ
автоматически выделить все поверхности. Для выбранного короткого блока
основным результатом остаётся 3D watershed из `boundary_study.py`.

## Интерпретация результатов

- PNG `material_XXXX` — бинарная маска материала с сохранением внутренних полостей.
- CSV.GZ `contours_XXXX` — замкнутые полилинии в исходных координатах, тип outer/inner,
  координаты оценок по градиенту/ISO50 и признаки поддержки. Контур замыкается
  соединением последней точки с первой в пределах одного ID.
- `seed_disagreement_XXXX` — разногласия схем инициализации, а не эталонная карта ошибок.
- `material_volume.npz` — маска выбранного блока, номера исходных срезов и сдвиг ROI.
- `surface_patch_voxels.ply` — открытый фрагмент поверхности выбранного блока, без
  искусственных крышек на торцах. Координаты в вокселях, Z=0 у первого среза блока.
- `study_metrics.json` — геометрические диагностики и чувствительность к параметрам.
  Число точек и процент поддержанных профилей не являются оценками точности.

Размер 75.4 мкм взят из существующего кода. Для метрологии нужны подтверждение
калибровки и эталонные границы хотя бы на нескольких сложных участках. Тесты на
аналитических фантомах проверяют локализацию на простой известной геометрии;
они не заменяют такую разметку реального КТ.

## Продолжение: объёмный градиент и адаптивный Canny

Новые результаты и PNG доступны в `results/canny3d_v2` через GitHub. Предпочтительный
вариант находится в `supported_refinement`: он сохраняет выбранную начальную
сегментацию и уточняет координаты X/Y/Z там, где есть поддержка адаптивного Canny.
Инициализация каждого блока указана в его `metrics.json`. Это исследование трёх
режимов, а не универсальное автоматическое правило выбора начальной маски.

`canny3d_study.py` вычисляет производные по трём осям, трёхлинейный 3D NMS,
локальные пороги с учётом шума и гистерезис по 26 соседям. Сравниваются Gaussian
и адаптивный диффузионный фильтр. Проверка направления и контраста используется
для опорных точек по разные стороны поверхности. Режим жёсткого наружного
приоритета оказался хуже на тонких стенках и сохранён как диагностический.

```bash
python -m unittest discover -s experiments -p test_canny3d.py -v
python experiments/canny3d_study.py --input CT_Test \
  --output /tmp/canny3d-new --blocks 500:524,738:762,976:1000 --outer-support

# Сохранённые начальные маски позволяют повторить уточнение без нового подбора:
python experiments/refine_canny3d.py --input CT_Test \
  --output /tmp/canny3d-refined --canny-results /tmp/canny3d-new \
  --thick-initializer results/canny3d_v2/supported_refinement \
  --thin-initializer results/experiments/final/volume
```

Для повторного получения начальной маски толстого блока: запустить
`canny3d_study.py --blocks 500:524 --no-outer-support` в новый каталог. Тонкий блок
использует сохранённую удачную прежнюю 3D-сегментацию; переходный — прежний
маркерный watershed по срезам. Переноса всей маски через сотни срезов здесь нет.

Файлы PLY записаны в вокселях. Срезовые CSV и наложения получены точным пересечением
уточнённой 3D-сетки с плоскостью среза. Слабые профили не смещаются; геометрически
опасные сдвиги уменьшаются с сохранением признаков. На торцах точки заморожены;
на крайних доступных срезах 500/1000 отсутствует двусторонний контекст для 3D NMS.
Точность на реальном КТ без контрольных границ не измерена.
Флаг `--outer-support` выше воспроизводит диагностический опыт с наружным
приоритетом; по умолчанию этот отвергнутый вариант выключен.
