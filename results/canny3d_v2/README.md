# 3D-градиент и адаптивный Canny: продолжение экспериментов

Цель — наружная поверхность и стенки внутренних каналов. Обработаны **75 реальных срезов в трёх блоках**: 500–524, 738–762, 976–1000. Исходные 16-битные TIFF и main.cpp не менялись.

**Для дальнейшей работы выбран вариант supported_refinement**: начальная сегментация сохраняется, поверхность уточняется по настоящему 3D-градиенту только при близкой поддержке адаптивного Canny. Инициализация для каждого блока явно записана в metrics.json: ориентированные 3D-рёбра для толстого сечения, прежний watershed по срезам для переходного, сохранённый прежний объёмный watershed для тонкого. Единого автоматического выбора инициализации здесь пока нет.

## Что добавлено

1. Производные по X, Y и Z после объёмного сглаживания; трёхлинейное подавление немаксимумов вдоль нормализованного 3D-градиента.
2. Адаптивный Canny: локальный Otsu на 3D-NMS, плитки 64×64 с контекстом по пяти срезам, смешивание с общим порогом и нижняя граница по MAD шума. Низкий порог = 0.4 высокого; гистерезис использует 26-соседство.
3. Сравнение Gaussian и адаптивного диффузионного фильтра Perona–Malik (8 шагов, kappa от оценки шума). Слабые продолжения Canny участвуют в барьере поверхности, но сами не создают новые полости.
4. Сильные границы задают пары опорных точек воздуха/материала по направлению градиента. Чтобы ошибочный знак контраста около тонкой стенки не разрывал оболочку, добавлена узкая опорная зона внутри независимо оценённого наружного контура. Это геометрический приоритет, а не измеренная толщина стенки.
5. Уточнение поверхности по максимуму производной вдоль 3D-направления **со смещением X, Y и Z**, максимум ±2 вокселя. Сдвиги, переворачивающие треугольники, сокращаются и явно помечаются. На торцах блока точки заморожены.
6. Контуры на PNG и CSV получены пересечением уточнённой 3D-сетки с плоскостью исходного среза, а не простой проекцией точек на XY.

## Диагностические варианты детектора и инициализации

Независимая инициализация по ориентированным рёбрам восстановила яркие каналы толстого сечения. На тонких стенках она дала разрывы. Жёсткий наружный приоритет также дал смещение в реконструкционные полосы и **не выбран для итогового уточнения**. Эти сравнения сохранены, чтобы видеть ограничения метода; правый столбец следующих изображений показывает этот экспериментальный вариант.

Три диагностические инициализации также не прошли проверку манифолдности рёбер сетки. Их PLY исключены из публикуемых результатов; причины и числа проблемных рёбер записаны в mesh_rejection.json. Для выбранного supported_refinement геометрическая проверка обязательна и пройдена.

Пройдены пять автоматических проверок: граница только по Z, реакция порогов на локальный шум, правильное пересечение сетки плоскостью, выделение материала/канала и XYZ-локализация для обоих фильтров. Полный вывод — [tests.log](tests.log).

## Экспорт и его проверка

Для каждого блока сохранены PNG рёбер и масок, CSV.GZ пересечений поверхности, NPZ координат до/после уточнения и PLY в вокселях. X/Y в PLY — координаты исходного изображения, Z=0 у первого среза блока. PNG масок обрезаны по ROI; его сдвиг записан в metrics.json и NPZ.
Проверены сохранённые PNG/NPZ/PLY: конечность координат, границы сдвига, порядок осей, невырожденность/ориентация граней, индексы, манифолдность рёбер и открытые края только на плоскостях обрезки. Подробности — [export_validation.json](export_validation.json).

## Что ещё не решено

Тонкие стенки и артефакты реконструкции всё ещё могут искажать локальные границы. Экспериментальная наружная зона внесла смещение и не применяется в выбранном supported_refinement; её толщина не является физическим измерением. В diagnostics сохранён вариант без этого приоритета для сравнения.
Выбор крупнейшей связной компоненты предполагает одну связную деталь в блоке и может удалить реальные отделённые фрагменты. Неподдержанные профили и геометрически ограниченные сдвиги не считаются достигшими максимума градиента; признаки сохранены в surface_coordinates.npz.
На крайних доступных срезах 500 и 1000 нет двустороннего Z-контекста, поэтому 3D NMS не выполняется в этих двух плоскостях. Сетки открыты на торцах блоков. Точность реального КТ без контрольной разметки не измерена; 75.4 мкм взято из прежнего кода и не калибровалось.

## Воспроизведение

Из корня репозитория, с зависимостями experiments/requirements.txt:
```bash
python -m unittest discover -s experiments -p test_canny3d.py -v
python experiments/canny3d_study.py --input CT_Test --output /tmp/new-canny3d --blocks 500:524,738:762,976:1000 --outer-support
```
Каталог каждого блока должен быть новым: скрипт не перезаписывает существующие результаты. Данные и код предыдущих опытов сохранены.
